WWebPerm

WWebPerm

new WWebPerm(WOrm, url, db, getUserByToken, verifyClientUser, verifyAppUser, optopt) → {Object}

Description:

  • 權限伺服器

    身分驗證責任(dspec/使用者身分驗證原則.md 第三節, 使用方套件標準註解): 框架(w-converhp、w-serv-hapi、w-serv-webdata、w-serv-orm)不驗證 token, 一律由本套件負責. 連線閘(verifyConn)與執行身分(getUserIdByToken)皆須完整驗證(token 有效、本系統使用者存在且啟用、部署方授權); hapi apis 路由各自驗證; 函數層級另檢查角色或成員; 公開入口只限列名者. 本套件之落實(perm-run01 起「權限後台與資料通道只限系統管理員」, 規則帳本 R-ADMIN-ONLY-01): 資料通道之連線閘(標頭 token, 所有入口: main 之 RPC／表 select／系統函數, 上傳下載各 apiType)與執行身分(請求本體 sysToken)、後台登入檢查(/api/getUserByToken)皆經 getAndVerifyAdminUser (外部 getUserByToken → perm users 存在且 isActive='y' → 部署方 verifyClientUser → perm users 表之列 isAdmin='y'; perm 以自身 users 表為權威, 不採 token 宣稱之 isAdmin), 任一關不過函數不執行(一般使用者即使部署方放行亦被拒, 回 userNotAdmin); 一般使用者(isAdmin='n')只能經 /api/getPerm 以 token 查本人權限樹; 改變狀態之 kpFunExt 函數(updateTargets／updatePemis／updateGrups／updateUsers)另保留 perm users 表中有效且 isAdmin='y' 之縱深檢查(requireAdmin), 不符回 userNotAdmin、零寫入; hapi apis 路由: getUserByToken(只限管理員)／getPerm(任何通過 verifyClientUser 之有效使用者, 回本人權限樹)驗 client 使用者, getPermUserInfor／syncAndReplaceTabs 驗 app 使用者(套件自行要求管理員等級, 再經 verifyAppUser); 無公開入口(前端靜態檔除外). 系統函數(dspec/使用者身分驗證原則.md 二.7、二.8; 規則帳本 R-SYSFUNCS-01): 本套件設定 sysFuncsPublic 為只公開 sys:getFuncList; [sys:polling](輪詢, 取走廣播與同步表時間戳)與 sys:getTableTags須有效身分—— 前端元件(w-serv-hapi 1.1.8／w-serv-webdata 1.1.16／w-serv-broadcast 1.1.12 起)於輪詢本體帶 sysToken, 每輪經 getUserIdByToken 反查(須為系統管理員; 缺 sysToken 鍵之輪詢不反查, 直接被拒). 因 getUserIdByToken 對空 token 與非管理員 fail-closed 且連線閘先擋, [sys:getFuncList] 實際仍須有效管理員身分. 登入前前端不連線(src/main.js 之 useWaitToken: true), 不依賴公開之系統函數; 已發布之舊前端建置檔(輪詢不帶 sysToken)升版後輪詢被拒, 使用者需重新載入頁面.

    token 種類與等級(使用者 2026-10-24 定案, dspec/使用者身分驗證原則.md 二之一; 規則帳本 R-APP-TOKEN-01): 使用者 token(一般使用者／系統管理員)代表登入者, 等級以 perm users 表之列判定; 應用系統 token(部署方 getUserByToken 回傳 isApp 為 'y')分兩種用途—— 使用者用途(以 userId 綁定使用者, 反查回所綁使用者之實際資料與 isApp='y'): 以所綁使用者之 perm users 列判定, 與其使用者 token 相同, 不需特別處理; 系統服務用途(不綁使用者, 代表外部應用系統本身)須同時: 不在 perm users 表、反查回 isApp='y'、isAdmin='y'、id 以 'app:' 開頭('app:<金鑰主鍵>'; sso 拒收以 app: 開頭之使用者主鍵): 可用管理員之後端服務(後台登入檢查、資料通道、四個寫入函數), 稽核欄記其 id; 不可用 /api/getPerm(無「本人」權限樹). 使用者用途綁定「不在 perm users 表之使用者」(如只存在於 sso 之管理員)不是系統服務用途(其 id 是該使用者之主鍵, 不以 'app:' 開頭), 於後台與資料通道被拒, 與其自身使用者 token 相同. 應用系統路由(/api/getPermUserInfor、/syncAndReplaceTabs)另採相容認定(改版預設相容): 呼叫者在 perm users 表者以該列為準(有效且 isAdmin='y'), 不在表者只看反查 isAdmin='y'(不要求 isApp 與 'app:' 前綴; 舊版 sso 之應用系統身分即 isAdmin='y', 未轉傳 isApp 之既有部署升版後不中斷), 一般使用者(isAdmin 非 'y')仍被拒. 高權限功能由專案方評估與負責, 套件不另設限(部署方可於 verifyAppUser 收緊; 系統服務用途經 verifyAppUser(user, from) 判定, from 為各入口名稱).

import WOrm from 'w-orm-lmdb/src/WOrmLmdb.mjs'
import WWebPerm from './server/WWebPerm.mjs'
import getSettings from './g_getSettings.mjs'


//st
let st = getSettings()

let url = st.dbUrl
let db = st.dbName
let opt = {

    serverPort: 11006,
    subfolder: '', //mperm
    urlRedirect: 'https://www.google.com/', //本機測試時得先編譯, 再瀏覽: http://localhost:11006/

    webName: {
        'eng': 'Permission Service',
        'cht': '權限管理系統',
    },
    webDescription: {
        'eng': 'A web service package for user permissions and management targets.',
        'cht': 'A web service package for user permissions and management targets.',
    },
    webLogo: 'data:image/svg+xml;base64,...',

}

let getUserByToken = async (token) => {
    // return {} //測試無法登入
    if (token === '{token-for-application}') { //提供外部應用系統作為存取使用者(應用系統token: 部署方須轉傳上游反查結果之isApp; 此例供/api/getPermUserInfor、/syncAndReplaceTabs使用, 不在users表者只看isAdmin為'y'; 若要同時使用後台與資料通道〔系統服務用途〕, id須以'app:'開頭)
        return {
            id: 'id-for-application', //如 sso 反查回 'app:<金鑰主鍵>'
            name: 'application',
            email: 'application@example.com',
            isAdmin: 'y',
            isApp: 'y',
        }
    }
    if (token === 'sys') { //開發階段w-ui-loginout自動給予browser使用者(且位於localhost)的token為sys
        return {
            id: 'id-for-admin',
            name: 'tester',
            email: 'admin@example.com', //mappingBy為email, 開發階段時會使用email找到所建置之使用者資料
            isAdmin: 'y',
        }
    }
    console.log('invalid token') //勿印權杖值
    console.log('於生產環境時得加入SSO等驗證token機制')
    return {}
}

let verifyClientUser = (user, from) => {
    console.log('verifyClientUser/user', user)
    // return false //測試無法登入
    console.log('於生產環境時得加入限制瀏覽器使用者身份機制')
    //本套件於此函數通過後，另要求資料通道與後台登入限系統管理員(perm users 表之 isAdmin 為 'y')，一般使用者仍可經 /api/getPerm(from 為 'getPerm')以 token 查本人權限樹，
    //故此處不可回傳 user.isAdmin === 'y'(會擋掉一般使用者之 /api/getPerm); 僅需放行有效之瀏覽使用者，或依 from 與自家政策再收緊(例如依來源網段或系統別拒絕)
    return true
}

let verifyAppUser = (user, from) => {
    console.log('verifyAppUser/user', user)
    // return false //測試無法登入
    console.log('於生產環境時得加入限制應用程式使用者身份機制')
    //本套件於此函數通過後另自行要求管理員等級(在users表者須為有效之系統管理員；不在表者只看getUserByToken反查之isAdmin為'y'，不要求isApp與'app:'前綴)，一般使用者即使本函數放行亦被拒(userNotAdmin)，故不必再以isAdmin判斷；僅需放行有效之應用系統，或依from與自家政策再收緊
    return true
}

//WWebPerm
let instWWebPerm = WWebPerm(WOrm, url, db, getUserByToken, verifyClientUser, verifyAppUser, opt)

instWWebPerm.on('error', (err) => {
    console.log(err)
})

getUserByToken function

輸入處理函數，函數會傳入使用者token，通過此函數處理後並回傳使用者資訊物件，並至少須提供'id'、'email'、'name'、'isAdmin'欄位，且'isAdmin'限輸入'y'或'n'。另可選提供'isApp'欄位('y'或'n'，未給視同'n'，行為與未提供此欄位之舊版相同)：部署方須轉傳上游(如w-web-sso)反查結果之'isApp'，'y'代表此token為應用系統token；使用者用途者(以userId綁定使用者)反查回所綁使用者之實際資料，在權限系統users表者以該列判定；系統服務用途者(不綁使用者，反查回id為'app:<金鑰主鍵>'即以'app:'開頭、'isApp'為'y'、'isAdmin'為'y'，其'email'、'name'可為空)四條件同時成立且不在users表時，可使用管理員之後端服務(後台登入檢查、資料通道)，須再經verifyAppUser；使用者用途綁定「不在users表之使用者」(如只存在於sso之管理員，其id為該使用者主鍵、不以'app:'開頭)不是系統服務用途，於後台與資料通道被拒，與其自身使用者token相同。應用系統路由(getPermUserInfor、syncAndReplaceTabs)採相容認定：呼叫者在users表者以該列為準(須有效且'isAdmin'為'y')，不在表者只看'isAdmin'為'y'(不要求'isApp'與'app:'前綴；舊版sso之應用系統身分即'isAdmin'為'y'，未轉傳'isApp'之既有部署升版後不中斷)，'isAdmin'非'y'者被拒(userNotAdmin)。注意: token 回傳之'isAdmin'僅供識別，權限系統對在users表者一律以自身users表該使用者之'isAdmin'欄位值為權威(不在users表者無列可依，系統服務用途以'isApp'、'isAdmin'皆為'y'且id以'app:'開頭認定，應用系統路由則只看'isAdmin')，不會被 token 宣稱之值複寫。函數拋錯或reject時視同查無使用者(回自家錯誤key，錯誤原文不回前端、不入log，只於srLog記warn)
verifyClientUser function

輸入驗證瀏覽使用者身份之處理函數，函數會傳入使用者資訊物件(perm users 表之列)與來源字串from，通過此函數識別後回傳布林值(可為Promise)，允許使用者回傳true，反之回傳false。from 值域: 'getUserByToken'(登入)、'getPerm'(api/getPerm)、以及資料通道之 apiType 'main'(RPC 與 ORM 執行; 連線閘驗標頭 token、執行身分〔getUserIdByToken〕驗請求本體 sysToken, 兩者各經本函數一次, 本體 token 與標頭 token 不同時兩個使用者各自驗證)、'upload-controller'、'upload-slice'、'download-get-filename'、'download-get-file'、'download'；資料通道與登入採同一授權強度(反查 perm users 且 isActive='y' 後再經本函數)；函數拋錯或reject時視同回傳false。本函數收到的是該列之淺層副本，改寫其欄位不影響本套件後續採用之執行身分與角色判定。本函數通過後，本套件另要求資料通道與後台登入(from 為 'getUserByToken'、'main'、'upload-controller' 等)限 perm users 表中 isAdmin 為 'y' 者(一般使用者即使本函數放行亦被拒，回 userNotAdmin)，故本函數不必再以 from 區分管理員與一般使用者，但可再收緊；一般使用者查本人權限樹之 /api/getPerm(from 為 'getPerm')仍會呼叫本函數，勿回傳 user.isAdmin === 'y' 而擋掉他們。勿以 isAdmin 判斷角色：非管理員由本套件統一拒絕並讓畫面顯示「無權進入權限後台」；若本函數先否決非管理員，使用者只會看到一般的「拒絕登入」並被轉址，看不到原因。本函數否決者（回傳false或拋錯，應只為非角色因素，如來源網段、系統別）一律回 userNoPermission，畫面為「拒絕登入」並轉址至opt.urlRedirect（開發環境延遲60秒）
verifyAppUser function

輸入驗證應用程序使用者身份之處理函數，函數會傳入使用者資訊物件(外部getUserByToken反查結果之淺層副本)與來源字串from，通過此函數識別後回傳布林值(可為Promise)，允許使用者回傳true，反之回傳false；函數拋錯或reject時視同回傳false。本函數通過後，本套件另自行要求管理員等級(應用系統路由 /api/getPermUserInfor、/syncAndReplaceTabs)：呼叫者在權限系統users表者以該列為準(須有效且isAdmin為'y')，不在表者只看反查結果isAdmin為'y'(不要求isApp與'app:'前綴)，一般使用者、使用者用途綁一般使用者、不在表且isAdmin非'y'者即使本函數放行亦被拒(userNotAdmin)，故本函數不必再以isAdmin判斷，但可再收緊(只能更嚴)；系統服務用途(不在表、isApp與isAdmin皆為'y'、id以'app:'開頭)亦會經本函數用於後台登入檢查與資料通道各入口(from 為 'getUserByToken'、'main'、'upload-controller' 等)，本函數否決者回 userNoPermission

輸入外部系統識別使用者token後所提供之資料物件，與權限系統之使用者資料物件，兩者間查找之對應欄位，可選'id'、'email'、'name'，未給或非此三者時為'id'，預設'id'。對應鍵須能唯一指出使用者：mappingBy為'email'或'name'時，外部同步(syncAndReplaceTabs)users之有效(isActive為'y')列，該欄位須為非空字串且與本批及其他from之有效列皆不重複(違規整批拒收invalidRows)；登入查找以對應鍵於權限系統users命中多於1筆有效使用者時一律拒絕(ambiguousUserFromPerm)，不取首筆；mappingBy為'id'(預設)時，後台列(from為空)以其id對應外部token使用者之id，外部同步列(from非空)則以其來源鍵srcKey對應(外部列之id為本系統配發之內部主鍵，不是登入識別；升版前同步寫入、尚無srcKey之舊外部列在首次匯入補上srcKey前暫以id對應)，並防止撞值(登入識別值須跨全表唯一，不論isActive、含他來源外部列；不同外部系統之使用者id碰撞常見而非同一人，已停用者之token不得對到他來源之有效列)：外部同步(syncAndReplaceTabs)批次內任一列之srcKey等於他來源任一既有列之登入識別值(後台列id、他來源外部列srcKey)時整批拒收(loginIdCollision，零寫入，請部署方改用可唯一對應之鍵，如以email對應並將mappingBy設為'email')、後台存檔(updateUsers)新增或改變之後台列id撞到任一外部列srcKey時整次拒收(loginIdCollision，零變更)，登入時若命中多於1筆(不論有效與否)則拒絕(ambiguousUserFromPerm)、恰命中1筆但已停用視同查無(cannotGetUserFromPerm)；mappingBy為'id'時getPermUserInfor之userId亦依此對應解析(外部列傳其srcKey、後台列傳id，不是內部id；命中多筆拒絕ambiguousUserFromPerm)，'email'／'name'時userId仍為perm內部id；升版前既有之跨來源重複srcKey歷史資料不阻擋存檔，但登入一律拒絕，請依README Upgrade Notes盤點處置
cascadeRename Boolean <optional>
 true

輸入群組、權限改名時是否連帶更新引用它之授權字串(users.cgrups、grups.cpemis)，預設true。改名以主鍵id判定(同id異名)，後台整表儲存與外部同步(同一from內)皆適用，於同一次寫入內改寫並可能寫入外部來源之users列之cgrups；給false則不連帶(引用成為懸空，視同引用查無對象而收嚴並於頁面提示)。群組、權限、標的被刪除時之引用連帶清理(users.cgrups、grups.cpemis、pemis.crules)不受此設定影響
lockExternalRows String <optional>
 'y'

輸入後台是否不得改外部列(from為非空字串，即經syncAndReplaceTabs由外部來源同步之列)，可選'y'或'n'，預設'y'。'y'時伺服端強制：後台新增列from須為空字串、外部列不可刪除、不可改from、身分/結構欄(指派欄與順序以外之欄位)不可改，違規整次拒收(saveFromNotAllowed／saveExternalRowChanged)；授權指派欄(users.cgrups、grups.cpemis、pemis.crules)後台可寫，但須附載入基準(用戶端自動附帶)，無基準者拒收(saveBaselineRequired)；外部列之order由外部擁有、後台儲存不重編。給'n'回到舊行為(僅保留from須為字串之檢查)。升版後既有庫中from為非空字串之列即視為外部列而唯讀，請先以g_fixFromType.mjs／g_purgeFrom.mjs盤點(見README Upgrade Notes)
