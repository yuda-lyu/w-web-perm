# 外部列保護與過期快照流程

## 觸發

管理員（瀏覽器使用者，經 w-ui-loginout 登入取得有效 token、`connState='csLogin'`）進入後台後，於 `LayoutContent.vue` 左側導覽點「管理使用者」（`mmUsers`）進入使用者清單頁（`LayoutContentUsers.vue`）、點「管理權限群組」（`mmGrups`）進入群組清單頁（`LayoutContentGrups.vue`）。兩頁各以 ag-grid（`WAggridVue`）列出其表之全部列，預設為編輯模式；本文件涵蓋 F-23「以外部同步為主」與 F-26「過期快照」兩項改動在這兩頁（含「管控所屬使用者」對話框 `VeGrupBlngUsers`、「管控使用權限」對話框 `VeCpemis`）之使用者可觀察行為，含瀏覽（橫幅、鎖頭、唯讀）與編輯（刪除、複製、儲存、對話框存檔）兩類；2026-10-22 run11 起另涵蓋「多人同時編輯」（使用者裁示 R-PRINCIPLE-00 原則 7）：清單頁與反向關聯對話框有未存編輯時他人或外部同步改了資料之提示、存檔拒收與重新載入（E2E-016～024，含權限頁 `LayoutContentPemis.vue`、標的頁 `LayoutContentTargets.vue` 與對話框 `VePemiBlngGrups`）。使用者 2026-10-21 裁示「開了外部同步就以外部為主」（依據：`sgud/rule/rulebook.md` R-PRINCIPLE-00 原則 3、5，`spec/設計要點與取捨.md` ADR-037）。

名詞：**外部列**＝`from` 為非空字串之列（經 `/syncAndReplaceTabs` 由外部來源同步進來者；`from` 為空字串、缺欄或非字串者為後台列，`src/js/externalRows.mjs:isExternalRow`）。伺服端 `opt.lockExternalRows`（預設 `'y'`，經 `getWebInfor` 帶給前端為 `webInfor.lockExternalRows`）為 `'y'` 時強制：外部列之身分／結構欄後台不得改、不得刪、不得改 `from`；授權指派欄（`users.cgrups`、`grups.cpemis`、`pemis.crules`）後台可寫，但須附載入基準；後台新增列 `from` 須為空字串。違規整次拒收、零寫入。

版面分區（兩頁相同）：標題區、功能區工具列（編輯模式開關、顯示欄位、新增、複製、刪除、儲存；`data-fmid="<表>-toolbar"`）、橫幅區（外部列提示與同步警示；`data-fmid="<表>-banner-ext"`／`"<表>-banner-warn"`，無內容時不渲染任何節點，畫面與 DOM 同改動前）、表格。進入後預設狀態：編輯模式開、無列被勾選、無儲存鈕。

四清單頁之外部列實作共用同一套純函數（`src/js/externalRows.mjs`、`src/js/externalUi.mjs`、`src/js/rowDigest.mjs`、`src/js/draftSync.mjs`）；外部列呈現之 e2e（E2E-001～015）只涵蓋使用者頁與群組頁，多人同時編輯之 e2e（E2E-016～024）涵蓋四清單頁與兩個反向關聯對話框各至少一案（見〈已知落差〉）。

## 重要流程

- **E2E-001**
  - title: 使用者頁顯示外部列橫幅與鎖頭
  - description: 管理員在左側選單點「管理使用者」進入使用者清單頁。當系統已開啟外部同步，且清單中有由外部來源同步進來的使用者時，清單上方會多出一條灰底橫幅，說明有幾筆資料由外部來源同步、其身分欄位在此唯讀且不可刪除、僅能修改授權指派設定；這些外部使用者的名稱儲存格左側各帶一個鎖頭圖示，滑鼠停留在鎖頭上會提示「由外部來源「來源名稱」同步，於此為唯讀。」。後台自行建立的使用者沒有鎖頭。此頁只呈現資訊，不寫入資料，也不需要特別前置；若看不到橫幅與鎖頭，表示目前沒有外部使用者，或系統管理者已關閉外部列保護。便於一眼分辨哪些使用者由外部來源管理、哪些可在此修改。
  - flow:
    - 測試資料：base seed 四位使用者（peter、mary、john、admin，`from` 皆為空）；案例前置（非使用者操作）：經外部同步端點（`/syncAndReplaceTabs`，app token）為 `users` 推入外部使用者 `ext-u1`（id `id-xr-u1`，`cgrups` 引用 權限群組M2）與 `ext-u2`（id `id-xr-u2`），`from` 為 `appExtU`。登入身分為管理員 token `sys`。

      3. 視覺（依序；兩張皆為進入頁面後之反應，屬觀察步驟，無點擊前圖）：檔名前綴 `test/pics/external-rows/external-rows-{eng,cht}-`：
         - 橫幅出現：框住外部列橫幅整條（灰底，緊貼上方工具列與下方表頭，框線置於間隙正中）→ `E2E-001-1-banner.png`

- **E2E-002**
  - title: 外部使用者列的身分欄不可編輯
  - description: 在使用者清單頁，外部使用者的名稱、電子郵件、說明三個儲存格雙擊後不會出現編輯框，是否為管理員與是否有效兩個核選方塊也呈灰色不能點，因為這些身分欄位由外部來源擁有。相對地，後台自行建立的使用者，例如種子資料中的 peter，雙擊名稱即可進入編輯，核選方塊也可以點。外部使用者列的「權限群組」按鈕仍可點開，因為授權指派由後台負責。這個流程只是檢視，不會修改任何資料，因此清單上方不會出現儲存鈕。若需要修改外部使用者的身分欄位，請到外部來源端處理。便於確認哪些欄位可在後台改、哪些要到外部來源端改。
  - flow:
    - 測試資料：同 E2E-001（base seed 四位使用者加外部使用者 ext-u1、ext-u2）。登入身分為管理員 token `sys`。
    - 操作：登入後台 → 點「管理使用者」頁籤 → 依序雙擊 ext-u1 之名稱、電子郵件、說明儲存格與 ext-u2 之名稱儲存格 → 雙擊 peter 之名稱儲存格（對照組；看到編輯框後按 Esc 取消）→ 觀察各列「是否為管理員」「是否有效」核選方塊 → 觀察 ext-u1 之「權限群組」按鈕。
    - 驗證：
      1. 語意：外部列各儲存格雙擊後，該儲存格內無編輯器輸入框（排除列勾選框；`input:not([type="checkbox"])` 為 0 個）；peter 之 name 雙擊後有編輯器輸入框（對照組，證明上列非選擇器失靈）。
      2. 語意：ext-u1、ext-u2 之 `isAdmin`、`isActive` 核選方塊皆 `disabled`；peter 之兩核選方塊不 disabled。
      3. 語意：ext-u1 之 `cgrups` 欄有且僅有一個按鈕且不 disabled（指派欄後台可寫）。
      4. 語意：全程無修改，清單頁不出現儲存鈕；庫內 ext-u1、ext-u2 逐欄等於夾具。
      5. 視覺：本案不設標準圖（唯讀檢視之畫面與 E2E-001 之鎖頭儲存格相同，核選方塊灰態屬既有元件樣式，不另設圖）。
    - 雙語：eng / cht 各一輪。
    - 清理：同 E2E-001。
    - 備註：外部列逐列唯讀以 `kpCellEditable.name／email／description` 為函式 `(params) => !isExternalRow(params.data)` 實作（`LayoutContentUsers.vue:genOpt`；ag-grid `editable` 接受函式，`w-aggrid-vue` 之 `setobj` 原樣傳遞）；核選方塊以 `:disabled="!isEditableIdentity || isLockedRow(props.row)"`。名稱欄內另有列勾選框，故判斷編輯器須排除 `checkbox`。實測（2026-10-22）：雙擊落點（儲存格中心）不落在勾選框或鎖頭上，後台列（peter）雙擊可開編輯器、按 Esc 取消後不留下修改狀態（儲存鈕不出現）。

- **E2E-003**
  - title: 經欄位挑選顯示來源欄且不可編

    - 驗證：

      2. 語意：兩個來源儲存格雙擊後皆無編輯器輸入框；清單頁不出現儲存鈕；庫內 ext-u1 之 `from` 仍為 `appExtU`、peter 之 `from` 仍為空。

    - 雙語：eng / cht 各一輪（「來源」項目文字語系不同）。
    - 清理：同 E2E-001。
    - 備註：`from` 欄不在 `kpCellEditable`，故對所有列唯讀（`LayoutContentUsers.vue:genOpt`；後台新增列 `from` 恆為空）。欄位挑選之 `showKeys(…, { applyOrder:false })` 維持欄序。實測（2026-10-22）：欄位挑選鈕之 mdi path（`test/tools/e2eExt.mjs` 之 `MDI_EXT.tableHeadersEye`）與已安裝之 `@mdi/js` 相同；彈窗內「來源」項以精確文字比對可命中（取第一個）；點工具列右側空白後即可雙擊儲存格；來源欄在 1440 寬下已渲染於 DOM。

- **E2E-004**
  - title: 勾選外部與後台使用者刪除只刪後台列
  - description: 管理員在使用者清單頁同時勾選一位外部使用者與一位後台自行建立的使用者，點工具列的「刪除勾選使用者」，畫面會先跳出提示「所選資料中有 1 筆由外部來源同步，無法在此刪除，已略過。」，點「確認」後只有後台使用者從清單移除，外部使用者仍在清單中，並出現儲存鈕；此時資料庫尚未變動，再點「儲存變更」才真正寫入，成功時出現「儲存使用者數據成功」。外部使用者不會被刪除，若要移除請到外部來源端處理。便於一次整理後台自建的使用者而不誤動外部資料。
  - flow:
    - 測試資料：base seed 四位使用者；案例前置（非使用者操作）：以管理者寫入 RPC（`updateUsers`）新增後台使用者 `bk-u1`（id `id-xr-bk1`，`from` 為空）；再經外部同步端點推入外部使用者 ext-u1、ext-u2（同 E2E-001）。登入身分為管理員 token `sys`。
    - 操作：登入後台 → 點「管理使用者」頁籤 → 勾選 bk-u1 與 ext-u1 兩列 → 點「刪除勾選使用者」→ 提示框點「確認」→ 點「儲存變更」→ 結果訊息框點「確認」。
    - 驗證：
      1. 語意：點刪除後出現單一訊息加「確認」鈕之警告框（非否／是確認框），訊息逐字為 `externalRowDelBlocked` 代入 `{n}`＝1（eng：`1 selected row(s) are synchronized from an external source and cannot be deleted here. They were skipped.`；cht：`所選資料中有 1 筆由外部來源同步，無法在此刪除，已略過。`）。
      2. 語意：點「確認」後 bk-u1 自清單移除、ext-u1 與 ext-u2 仍在、不再出現任何彈窗（後台使用者不被任何資料引用，直接移除）、出現儲存鈕；此時庫內仍有 bk-u1（只自清單移除，未寫入）。
      3. 語意：點儲存後出現 `userSaveUsersSuccess`；庫內無 bk-u1，ext-u1、ext-u2 逐欄等於夾具，總筆數為 6。
      4. 視覺（依操作序；檔名前綴 `test/pics/external-rows/external-rows-{eng,cht}-`）：
         - 點擊前：框住工具列之「刪除勾選使用者」鈕 → `E2E-004-1-click-delete.png`
         - 點擊後：框住警告框（整個彈窗面板含標題、訊息與「確認」鈕）→ `E2E-004-2-blocked-box.png`
         - 各張與 baseline 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：案例結束以 `restoreTables` 還原（外部夾具直刪、後台列由整表寫回快照移除），回驗三表筆數皆為 4。
    - 備註：`LayoutContentUsers.vue:deleteItemsCheck` 以 `splitCheckedRows` 先濾除外部列並以 `showCheckYes(…, { type:'warning' })` 提示筆數，按確認後才對其餘列進入既有刪除流程；伺服端另以 `saveExternalRowChanged` 拒收任何刪除外部列之寫入（api 層覆蓋）。後台使用者不被任何表引用，故無引用連帶確認框。實測（2026-10-22）：兩個核選方塊皆可勾（外部列之勾選框未被停用）；警告框為 `showCheckYes` 單一訊息形狀（標題、訊息、確認）；`probeStuckTooltip` 未因點擊刪除鈕後之提示框殘留而擋下截圖。

- **E2E-006**
  - title: 複製外部使用者後新列不再受鎖定

## 規則摘要

- **權限**：本檔案例皆為管理員（token `sys`）之畫面軸行為；寫入經 `verifyConn` → `checkToken` → `getAndVerifyClientUser` 守門（同 `流程_後台群組清單.md`）。同步端點經 app token（`verifyAppUser`）。外部列保護屬資料主從規則（外部來源為主、指派欄為後台主），非權限分軸。
- **外部列判定**：`from` 為非空字串；`''`、缺欄、非字串（null、數字、布林）皆為後台列（`isExternalRow`）。前端提示（橫幅、鎖頭、唯讀、刪除濾除）只在 `webInfor.lockExternalRows==='y'` 時啟用；伺服端為強制者，前端不取代伺服端守門。
- **指派欄可寫但須附基準**：`users.cgrups`、`grups.cpemis`、`pemis.crules` 後台可寫；修改外部列之指派欄須附載入基準，無基準拒收 `saveBaselineRequired`；基準隨「草稿所依據之那份列」同時產生（清單頁於 `changeParams` 重建 items 時；對話框於 `show()` 時），不得於存檔當下由最新 store 計算。
