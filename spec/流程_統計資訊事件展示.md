# 統計資訊事件展示流程

## 觸發

管理員於後台左側導覽點「統計資訊」（`mmStaInfor`，第一頁籤）進入統計頁。頁面以兩個區塊呈現後端 `srLog` 所記事件（event）之發生情形：

- **事件發生頻率**（折線圖）：每個 event 各一條折線，於圖表圖例點擊即可切換要顯示哪些 event；另可加上「全部加總」總和線、切換時間分組（每小時 / 每日）。圖例位於圖頂：放得下時可換行列出全部事件；放不下（換行後會壓到圖表最上方刻度）時改為單列，右側顯示翻頁箭頭與頁次（規則見〈補充〉圖例排版）。
- **事件統計表**：各 event 為一列、依「最近 1 日」次數由多到少排序，欄位含 最近 1 日 / 最近 8 小時 / 最近 4 小時 / 最近 1 小時。

兩區塊資料分別由後端 `getStaEvent`（時序分桶）與 `getStaEventTable`（各時間窗計數）提供。

## 重要流程

本流程於 e2e-stainfor 以「後端注入確定性虛擬數據」驗證：後端以統計虛擬數據模式啟動後，`getStaEvent` / `getStaEventTable` 回傳**固定確定性資料集**（5 個事件 `verifyConn` / `updateTargets-success` / `checkUser-error` / `api/getPerm-success` / `getWebInfor-success`，計數不依現在時間），使折線圖與統計表之像素穩定可比對（取代難以穩定的真實 wall-clock 統計，免用貼圖覆蓋）。E2E-008 另以「多事件」虛擬數據（`staEventMock:'many'`，同形資料集改為 13 個名稱較長之事件，`server/procStaInfor.mjs` `MOCK_EVENTS_MANY`）啟動。視窗預設 1440×900（導覽區並排時圖寬 1140）。eng / cht 各一輪。重點觀看區以紅框（#f26 / 5px）標注。

## 補充

- **時間分組下拉**（2026-09-14）：原為原生 `<select>`（彈出清單之選中／滑過底色由作業系統決定，與本頁主題不一致），改為自製 `WTextSelect`，色票沿用本頁 Tailwind 實值（邊線 #e5e7eb、底 #ffffff、文字 #111827、項目 hover #f3f4f6、焦點邊線 #3b82f6、展開圖標 #6b7280），寬度依當前語系最長選項文字實寬計算（`timeIntervalSelWidth`），與 w-web-sso 統計頁三個時間粒度下拉、w-web-api 時間範圍下拉同構；部署方 `rddmanager_2_perm` 2026-09-14 建議書項目，屬三套件一致性修正。

- **為何用確定性虛擬數據**：真實事件統計依 wall-clock 分桶且 ECharts canvas 跨進程有次像素漂移，pixel baseline 難穩定。後端虛擬數據模式回固定資料集，使圖表/表格內容完全確定，pixel 比對穩定，無需對動態區做貼圖覆蓋遮蔽。
- **事件篩選由圖例提供**：圖表預設呈現全部事件；使用者於圖例點掉不看的事件（尤其只留 error 類，如 `checkUser-error` / `api/*-error`）即可單獨觀察其趨勢與尖峰，支援趨勢辨認與危險識別，而非把所有事件混為一談。頁面不另設事件勾選清單，避免與圖例重複同一功能。
- **圖例排版**（2026-09-24，ADR-024）：事件圖之圖例置於圖頂（`top:0`）。一般式（可換行）圖例放得下時維持一般式；放不下時改為捲動式（單列，右側左右箭頭與頁次，echarts `legend.type:'scroll'`）。「放得下」之判準為一般式圖例文字之底緣 ≤ 57 像素（相對圖頂）：繪圖區頂明定為 65（`LayoutContentStaInfor.vue:425`，同 echarts 6.1.0 預設），最上方 y 軸刻度文字以繪圖區頂為中線、字高 12 → 字頂 59，再留白 2。實測（echarts 6.1.0，列距 21）：1 列底 18、2 列底 39、3 列底 60（擦到刻度）、4 列底 81（壓進繪圖區），故實際上等同「最多兩列」。判定以離屏 echarts 實例量測一般式圖例於當下圖寬之排版（`src/js/legendFit.mjs` `createLegendMeasurer`），為事件名稱與圖寬之函數，不讀可見圖、不在可見圖上試排；於圖表設定更新後（`LayoutContentStaInfor.vue:516-518`）與圖表容器尺寸與圖不一致而重繪後（`autoresizeEvent.onResize`，`:251`；w-echarts-vue ≥1.0.15，含圖剛建立之同一幀）判定。類型不變時不動圖例（捲動式之頁次保留）；類型改變時帶齊圖例設定並帶入目前之隱藏狀態（`:547-553`），一般式無頁次，故由一般式再切回捲動式時回到第 1 頁。捲動式之事件名稱可能長於可視窗而被截斷，滑鼠移到名稱上顯示全名（`legend.tooltip`，`src/js/legendFit.mjs` `genLegend`）。
  - 不變條件（e2e 每個觀察點皆驗，`test/tools/e2e-setup.mjs` `assertStaLegendLayout`）：圖寬＝圖表容器寬；每個事件皆有圖例項目；圖例頂 ≤ 10；圖上類型＝元件判定之類型；圖例文字底緣 ≤ 57；捲動式為單列。
  - 門檻實例（2026-09-24 實測，echarts 6.1.0、Windows 預設字型；圖寬＝視窗寬 − 300，導覽區收合或視窗 < 460 時為 − 100）：5 事件於圖寬 431 以上為一般式（視窗 731 以上；加總不論語系亦同）；13 事件於圖寬 1101 以上、加 `Total` 1130 以上、加 `全部加總` 1150 以上為一般式（2026-09-25 逐 1px 實測，門檻下一像素皆為 3 列、底 60）。
- **e2e 之 act 一律走 user-facing**（點選單、點圖例、點翻頁箭頭、勾全部加總、點導覽區圓鈕、點頂列語系下拉、改視窗寬），不以程式直設狀態；圖例畫於 canvas 內無 DOM 節點，故以圖表實例查出圖例文字與翻頁箭頭之視窗座標後，以真滑鼠點擊該座標；捲動式時只點可視窗內之事件。
- **載入狀態（先到先畫，ADR-021）**：進頁即渲染頁首與兩張卡片骨架；「事件發生頻率」圖區在資料未到前以與圖同高（300px）之轉圈佔位、「事件統計表」以轉圈佔位，兩支 API 並行、各自到達即渲染，不等最慢者；無整頁「等待數據中…」。任一 API 失敗仍整頁顯示載入失敗訊息。載入完成後 DOM 與先前一致，本流程各 baseline 不受影響。切換時間分組時既有圖維持顯示直到新資料到達。
- **後端統計掃描（ADR-021）**：`getStaEvent` 走單趟掃描 + 檔級彙總快取（封閉小時檔只掃一次），`getStaEventTable` 掃近 25 小時之檔並交 worker；兩者以 wsemi cache 30 秒快取（自掃描完成起算、失敗不快取）。非 mock 模式之數值語意由 `test/unit-staEvent-golden.test.mjs` 以改造前實作產出之 expected 守護。
