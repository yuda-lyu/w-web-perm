# 統計資訊事件展示流程

## 觸發

管理員於後台左側導覽點「統計資訊」（`mmStaInfor`，第一頁籤）進入統計頁。頁面以兩個區塊呈現後端 `srLog` 所記事件（event）之發生情形：

- **事件發生頻率**（折線圖）：每個 event 各一條折線，於圖表圖例點擊即可切換要顯示哪些 event；另可加上「全部加總」總和線、切換時間分組（每小時 / 每日）。
- **事件統計表**：各 event 為一列、依「最近 1 日」次數由多到少排序，欄位含 最近 1 日 / 最近 8 小時 / 最近 4 小時 / 最近 1 小時。

兩區塊資料分別由後端 `getStaEvent`（時序分桶）與 `getStaEventTable`（各時間窗計數）提供。

## 重要流程

本流程於 e2e-stainfor 以「後端注入確定性虛擬數據」驗證：後端以統計虛擬數據模式啟動後，`getStaEvent` / `getStaEventTable` 回傳**固定確定性資料集**（5 個事件 `verifyConn` / `updateTargets-success` / `checkUser-error` / `api/getPerm-success` / `getWebInfor-success`，計數不依現在時間），使折線圖與統計表之像素穩定可比對（取代難以穩定的真實 wall-clock 統計，免用貼圖覆蓋）。eng / cht 各一輪。重點觀看區（事件卡片 / 統計表卡片）以紅框（#f26 / 5px）標注。

- **E2E-001**
  - title: 進統計頁後每事件各一條折線
  - description: 驗證進入統計頁後，「事件發生頻率」圖以每個事件一條折線呈現，可區分各事件趨勢。本案為預設總覽態：5 個虛擬事件各一條折線、圖例列出全部事件。
  - flow:
    - 測試資料：後端以確定性虛擬數據啟動，回傳固定 5 事件之時序分桶（計數固定、不依現在時間）。
    - 操作：登入進入後台 → 點左側「統計資訊」→ 等事件頻率圖渲染。
    - 驗證：
      1. 語意：頁面出現「事件發生頻率」標題；圖表卡片內圖表已渲染（canvas 存在）；圖表系列恰為 5 個事件、含 `verifyConn` 等事件名。
      2. 視覺：與 baseline `test/pics/stainfor/stainfor-{eng,cht}-E2E-001-event-all.png` 視覺一致（pixelmatch 反鋸齒感知 + maxDiffPixels 容差，非 byte-exact），紅框標注事件頻率卡片。
    - 雙語：eng / cht 各一輪。
    - 清理：測試後還原後端為預設（非虛擬數據）設定。

- **E2E-002**
  - title: 由圖例關掉其餘事件時圖表僅呈現保留事件
  - description: 驗證使用者在圖表圖例點掉其餘事件後，圖上僅留所選事件的折線、被關掉者之圖例呈灰階——此為針對單一/少數事件做趨勢辨認、危險識別的能力，圖例為此篩選之唯一入口。本案只保留 2 個事件（`verifyConn`、`checkUser-error`）。
  - flow:
    - 測試資料：同 E2E-001（後端確定性虛擬數據，5 事件）。
    - 操作：進統計頁 → 於圖表圖例逐一點掉其餘 3 個事件、僅保留 2 個事件 → 等圖表重繪。
    - 驗證：
      1. 語意：圖例狀態顯示保留之 2 事件為顯示中、被點掉之 3 事件為不顯示。
      2. 視覺：與 baseline `test/pics/stainfor/stainfor-{eng,cht}-E2E-002-event-selected.png` 視覺一致（pixelmatch 容差），紅框標注事件頻率卡片。
    - 雙語：eng / cht 各一輪。
    - 清理：測試後還原後端為預設設定。

- **E2E-003**
  - title: 勾全部加總時圖表加入單一總和線
  - description: 驗證使用者勾選「全部加總」後，圖表於各事件折線之外再加入一條「全部加總（Total）」總和線（所有事件次數加總），供整體量級總覽；此時圖上共 6 條系列（總和線 + 5 事件）。
  - flow:
    - 測試資料：同 E2E-001（後端確定性虛擬數據）。
    - 操作：進統計頁 → 勾「全部加總」→ 等圖表重繪。
    - 驗證：
      1. 語意：圖表系列共 6 條、首條系列名為「全部加總 / Total」（staTotal）；圖表 canvas 存在。
      2. 視覺：與 baseline `test/pics/stainfor/stainfor-{eng,cht}-E2E-003-event-total.png` 視覺一致（pixelmatch 容差），紅框標注事件頻率卡片。
    - 雙語：eng / cht 各一輪。
    - 清理：測試後還原後端為預設設定。

- **E2E-004**
  - title: 事件統計表各事件為列並依最近一日次數降序
  - description: 驗證「事件統計表」以各事件為一列、依「最近 1 日」次數由多到少排序呈現，欄位含 最近 1 日 / 最近 8 小時 / 最近 4 小時 / 最近 1 小時，供快速辨識高頻事件。本案以 5 個虛擬事件之固定窗計數呈現。
  - flow:
    - 測試資料：後端以確定性虛擬數據啟動，回傳固定 5 事件之各時間窗計數（最近 1 日 > 8 小時 > 4 小時 > 1 小時，各事件最近 1 日次數互不相同以使排序明確）。

## 補充

- **為何用確定性虛擬數據**：真實事件統計依 wall-clock 分桶且 ECharts canvas 跨進程有次像素漂移，pixel baseline 難穩定。後端虛擬數據模式回固定資料集，使圖表/表格內容完全確定，pixel 比對穩定，無需對動態區做貼圖覆蓋遮蔽。
- **事件篩選由圖例提供**：圖表預設呈現全部事件；使用者於圖例點掉不看的事件（尤其只留 error 類，如 `checkUser-error` / `api/*-error`）即可單獨觀察其趨勢與尖峰，支援趨勢辨認與危險識別，而非把所有事件混為一談。頁面不另設事件勾選清單，避免與圖例重複同一功能。
- **e2e 之 act 一律走 user-facing**（點選單、點圖例、勾全部加總），不以程式直設狀態；圖例畫於 canvas 內無 DOM 節點，故以圖表實例查出圖例文字之視窗座標後，以真滑鼠點擊該座標。
- **載入狀態（先到先畫，ADR-021）**：進頁即渲染頁首與兩張卡片骨架；「事件發生頻率」圖區在資料未到前以與圖同高（300px）之轉圈佔位、「事件統計表」以轉圈佔位，兩支 API 並行、各自到達即渲染，不等最慢者；無整頁「等待數據中…」。任一 API 失敗仍整頁顯示載入失敗訊息。載入完成後 DOM 與先前一致，本流程各 baseline 不受影響。切換時間分組時既有圖維持顯示直到新資料到達。
- **後端統計掃描（ADR-021）**：`getStaEvent` 走單趟掃描 + 檔級彙總快取（封閉小時檔只掃一次），`getStaEventTable` 掃近 25 小時之檔並交 worker；兩者以 wsemi cache 30 秒快取（自掃描完成起算、失敗不快取）。非 mock 模式之數值語意由 `test/unit-staEvent-golden.test.mjs` 以改造前實作產出之 expected 守護。
