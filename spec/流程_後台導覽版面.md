# 後台導覽版面流程

## 觸發

管理員登入後台後，畫面由左側導覽區與右側內容區組成（`LayoutContent.vue`）。導覽區列出五個頁籤（`mmStaInfor` / `mmTargets` / `mmPemis` / `mmGrups` / `mmUsers`），預設停在「統計資訊」（`menuKey` 初值 `mmStaInfor`，`LayoutContent.vue:169`）。導覽區右上角有「隱藏選單」圓鈕（`mdiArrowLeftBoldHexagonOutline`，`LayoutContent.vue:45-62`，僅 `drawer` 為真時渲染）；點擊後導覽區收合，內容區左上角改出現「顯示選單」圓鈕（`mdiArrowRightBoldHexagonOutline`，`LayoutContent.vue:101-118`，僅 `drawer` 為假時渲染），點擊即恢復導覽區。兩顆圓鈕互斥，同一時間只有一顆存在。

`drawer` 狀態以 prop 傳入五個內容頁（`LayoutContent.vue:73-96`）：收合時各頁標題區加左側內距，讓出「顯示選單」圓鈕所佔位置——四個資料頁於標題列 padding 由 `5px` 改 `5px 5px 5px 20px`（如 `LayoutContentUsers.vue:17`），統計頁於標題區塊加 `padding-left:20px`（`LayoutContentStaInfor.vue:18`）。

導覽區另隨瀏覽器視窗寬度自動切換（`LayoutContent.vue:18-22`）：視窗寬度由門檻以上縮到門檻以下時，導覽區自動收合，並改為「浮動」模式——之後在窄視窗按「顯示選單」，導覽區浮在內容區上方、其餘內容覆蓋灰色遮罩，點遮罩即收合；視窗由門檻以下拉寬到門檻以上時，導覽區自動展開並恢復「並排」模式（導覽區排在內容區左側、內容區讓位）。門檻為導覽區寬度 × 2.3（預設寬 200 → 460 像素；導覽區右緣可拖曳改寬，範圍 150～300，門檻隨之改變）。本文件涵蓋導覽區以圓鈕或視窗寬度收合／恢復，以及各頁標題讓位；各頁內容之瀏覽與編輯屬各頁流程文件。

## 重要流程

本流程於 e2e-layout 驗證。統計頁為預設頁且其圖表資料隨時間變動，故後端以統計虛擬數據模式（`staEventMock`）啟動，使統計頁截圖為確定性內容（同 e2e-stainfor）。eng / cht 各一輪。視覺項每步兩張：點擊前框住要點的圓鈕，點擊後框住有反應的元素；紅框（#f26 / 5px）以截圖後疊圖方式標注。標準圖檔名前綴 `test/pics/layout/layout-{eng,cht}-`。

## 規則摘要

- **互斥圓鈕**：「隱藏選單」與「顯示選單」由同一 `drawer` 布林決定，永遠只渲染其中一顆（`LayoutContent.vue:47,102`）。
- **讓位為各頁各自負責**：`drawer` 以 prop 傳入五頁，各頁自行在標題區加左內距；新增內容頁時須比照，否則收合後標題會被「顯示選單」圓鈕壓住（本流程 E2E-001 之語意項逐頁量測即為此守門）。
- **就緒訊號**：收合／展開為 WDrawer 平移動畫（300ms），以使用者可觀察幾何為準——目標圓鈕出現、導覽面板 `[ev-stable]` 與內容區 rect 連續取樣不變（展開 x=0 寬 200；收合 `display:none`），不以固定等待時間判定；WDrawer 內部 `[state]` 標記於 w-component-vue 2.5.13 偶發卡在 `hiding`/`opening`（2.5.14 已修，見〈已知落差〉），本流程不以其為判準。
- **統計頁確定性**：統計頁為預設頁，其圖表資料隨 log 變動，截圖須在 `staEventMock` 模式下進行（同 e2e-stainfor）。
- **寬度自動切換**（`LayoutContent.vue:18-22`，實作於 `WDrawer.vue:536-590`）：只在寬度「跨越」門檻時觸發——縮窄跨門檻且導覽區展開中 → 收合並改浮動；拉寬跨門檻且導覽區收合中 → 展開；拉寬跨門檻且目前之浮動是縮窄時自動造成者 → 恢復並排。未跨門檻之縮放（如 1440 ↔ 700）不切換。導覽區初次出現時不依當下寬度判斷，窄視窗直接開頁之情形見〈已知落差〉。

## 已知落差

- **已修復（附修復紀錄）** 2026-09-14：WDrawer 根節點 `[state]` 於收合／展開後偶發停在 `hiding` / `opening` 達 200 秒（w-component-vue 2.5.13 `WDrawer.vue:688,740` 之 `waitFun` 兜底 800×250ms），視覺於 300ms 內正常落定、使用者看不出；根因為 wsemi 1.8.92 `domIsStable.mjs` core() 丟棄 await 前觀察到的進行中動畫，高負載下 transition 之 pending 期超過 100ms 時整輪誤判穩定，而 `v-domstable` 只在翻轉時 emit、WDrawer 又依賴該 emit。後果：依賴 `[state]` 之 e2e 就緒訊號（`test/tools/e2e-setup.mjs` `waitDrawerReady`）每張多等 10 秒才放行。修復：wsemi 1.8.94 `domIsStable.mjs` 改為 await 前動畫數 + await 後再比 rect 且只計 running 之有限動畫；w-component-vue 2.5.14 `WDrawer.vue` 以 `transitionend` / `transitioncancel` 為主要訊號、指令回報為輔（`settleState`），兜底縮為動畫時長 + 1 秒。同日以 8 輪截圖後收合驗證 0 卡住、`state` 於 0.5 秒內落定。本流程仍以幾何為就緒訊號（使用者可觀察），`[state]` 於修復後亦可靠。

- **已修復（附修復紀錄）** 2026-09-14：統計頁未為「顯示選單」圓鈕讓位——`LayoutContentStaInfor.vue` 已宣告 `drawer` prop 但模板未使用，收合後圓鈕（x=−1..35, y=58..94）與標題「統計資訊」墨跡（x=30..126, y=80..112）重疊 5×14px（部署方 `rddmanager_2_perm` 於 1600×900 實測，證據 `rddmanager_2_perm/spec/evidence/bckfix_C_probeDrawer.log`；四個資料頁已正確讓位）。修復：標題區塊加 `:style="drawer ?
