# 後台使用者清單流程

## 觸發

管理員（瀏覽器使用者，經 w-ui-loginout 登入取得有效 token、`connState='csLogin'`）進入後台後，於 `LayoutContent.vue` 左側導覽點「使用者」（`mmUsers`）進入使用者清單頁（`LayoutContentUsers.vue`）。此頁以 ag-grid（`WAggridVue`）列出 `users` 表，提供：編輯模式切換、顯示欄位挑選、新增 / 複製 / 刪除 / 儲存、`cgrups` 群組關聯入口按鈕、`isAdmin` / `isActive` 就地切換。

寫入端點 `updateUsers` 經 hapi `verifyConn` → `checkToken(token)` 守門（`server/WWebPerm.mjs:1049,1063`），**token 無效 / 過期一律拒絕連線**；是否限定管理員由部署方的 `verifyClientUser` 決定（開發樣本限 `isAdmin='y'`，`srv.mjs`）。

- **E2E-012**
  - title: 僅可調整群組指派的部署模式下編輯使用者所屬群組並儲存
  - description: 使用者身分由外部單一登入系統同步的部署，會將本系統設定為「僅可調整使用者所屬群組」。此時管理員進入「使用者」頁即為編輯模式，但工具列只有編輯模式開關與顯示欄位挑選，沒有「新增使用者」按鈕；名稱、電子郵件、說明、來源等儲存格不能就地編輯，「系統管理員」與「是否有效」的勾選也不能點。仍可點某列「權限群組」按鈕開啟「編輯使用權限群組」對話框，勾選要加入的權限群組後點對話框的儲存，回到清單即可看到該列的群組數更新，工具列出現「儲存變更」按鈕；點下後看到「儲存使用者數據成功」，該使用者所屬群組已寫入資料庫，其餘身分資料維持不變；若後端拒絕則看到「儲存使用者數據失敗」與原因，資料不會寫入。此模式適合把使用者建立與身分維護交給單一登入系統，而只在本系統決定每個人擁有哪些權限群組的情境。

## spec 規則摘要

- **權限**：所有 `updateUsers` 寫入經 `verifyConn` → `checkToken` 守門（有效 token 才可寫）；是否限管理員由部署方 `verifyClientUser` 決定（開發樣本限 `isAdmin='y'`）。
- **粒度**：欄位錯誤走 cell 警告 icon + tooltip（具體 5 種）；Save 擋存彙整（`errInNames` / `errInEmails` 粗 2 種）與操作結果（成功 / 失敗 / 空）一律走 `$dg.showCheckYes` 持久 modal（showCheckYes 前先 `updateLoading(false)`）；非預期例外（外層 catch）保留 `$alert` toast。
- **邊界**：
  - `users` **允許 name 重複**（僅前端警告、後端不擋）；`email` 不可空 / 不可重複（前端 + 後端 `ckKey` 雙守門）。
  - CRUD 為「單頁多動作 + 批次儲存」模型：`addItem` / `copyItem` / `deleteItemsCheck` / `toggle*` / `showVeCgrupsById` 只改 `opt.rows` 並設 `isModified=true`，**不即時打 API**；一律 Save 才以 `ltdtDiffByKey` 批次 del / insert / save 送出。
  - 稽核欄位（`userId` / `time*`）前端填 `{待自動給予}` 佔位符，後端 `procOrm` 補實值。
  - `isError` / `errItemsByName` / `errItemsByEmail` 為前端 computed 驗證；name 重複只警告不擋存（僅 email 與必填擋）。
  - loading 於 `core()` 內、在 `isError` / rows 空兩同步檢查**之後**才開啟（`LayoutContentUsers.vue:1190`）；早退分支不開 loading，符合全域 §5.1 canonical（`updateLoading` 應在同步檢查後）。
- **契約**：`saveUsers` 為按鈕 handler，第一行 `msg.pm.resolve()` 釋放視覺鎖後 fire-and-forget 呼叫 `doSaveUsers`；`doSaveUsers` 內 `core() + finally`，`finally` 一處關 loading（`LayoutContentUsers.vue:1217`）；`updateUsers` 失敗由其 inline `.catch` 顯示失敗提示，並以 `okSave` 旗標 `if (!okSave) return` 短路後續。

## 已知落差

- **設計事實（記錄備查）** 2026-09-16：本頁 `isAdmin` / `isActive` 兩欄之儲存格內為原生 checkbox（可聚焦），但 `kpHeadFocusHighlight` 只對 `cgrups` 欄關閉（`LayoutContentUsers.vue:232-233,751-753`），故這兩欄之 checkbox 取得焦點時儲存格仍畫出 `#0091ea` 焦點框，與同頁 `cgrups` 欄及四個關聯對話框「儲存格內有自己的控制項即關閉焦點框」之規則不一致。此為既有行為（非 2026-09-16 關聯彈窗改版所引入），且屬**視覺**呈現差異而非互動行為差異（依全域 §8，視覺不對稱適用真痛三條件，功能與可達性皆不受影響），故不隨本次改版一併調整；若日後要統一，須同時重產使用者頁全部標準圖。
- **已修復（附修復紀錄）** 2026-09-17：「顯示欄位挑選」中先取消勾選某欄再重新勾選，該欄會跑到最右而非回到原位；四個清單頁（使用者／群組／權限／標的）皆同。成因鏈：①`w-component-vue` 之 `WInputCheckbox.vue:379-381` 重新勾選時把該項 push 到 v-model 陣列尾端；②頁面把該陣列交給 `showKeys`；③`w-aggrid-vue` 2.0.87 之 `showKeys` 固定以 `applyOrder:true` 依該陣列順序重排欄位。修復：`w-aggrid-vue` 升至 2.0.88（`showKeys` 新增 `opt.applyOrder`，預設仍為 `true`），四頁之 `toggleTabKeys` 改呼叫 `showKeys(tabKeysShow, { applyOrder: false })`，只切換顯示與隱藏、維持目前欄序（`LayoutContentUsers.vue` / `LayoutContentGrups.vue` / `LayoutContentPemis.vue` / `LayoutContentTargets.vue` 之 `toggleTabKeys`）。`showKeys` 僅於勾選時呼叫、初始欄序由 `opt.keys` 決定，故初始畫面不受影響；`tabKeysShow` 另一處用途為 `arrPull` 求隱藏集合，與順序無關。驗收（`tmp/probe-showkeys-order.mjs`，真實點擊表頭眼睛鈕與勾選項）：四頁各取「右側仍有可見欄」之欄取消再勾回，欄序與操作前完全一致；同頁以舊行為（`applyOrder:true`）為對照組，四頁皆重現「該欄跑到最右」，證明驗收具鑑別力。原載「成因在元件庫、非本專案頁面層可單獨修正」一句於套件補上選項後已不成立。
