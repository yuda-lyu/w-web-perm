# 群組權限關聯流程

## 觸發

管理員（瀏覽器使用者，經 w-ui-loginout 登入取得有效 token、後端 `verifyConn` 守門）進入後台後，可由兩個入口進入「群組與權限的關聯」編輯。兩入口操作的是同一份資料 `grups.cpemis`（一個 JSON5 字串，結構為 `{ 權限名: { mode: 'OR'|'AND', isActive: 'y'|'n' } }`），差別只在切入角度：

- **群組清單頁入口**：於 `LayoutContentGrups.vue` 列出 `grups` 表，`cpemis` 欄渲染為一顆按鈕（顯示已啟用權限數量）；點該按鈕呼叫 `showVeCpemisById(id)`（`LayoutContentGrups.vue:227,1130`），開啟群組權限關聯對話框 `VeCpemis`。此對話框以「該群組擁有哪些權限」為視角，逐列權限可勾選啟用（`enable`）、選 OR / AND 合併模式（`mode`）。

- **權限清單頁入口**：於 `LayoutContentPemis.vue` 列出 `pemis` 表，`belongGrups` 欄（表頭「管控所屬權限群組」）渲染為一顆按鈕（顯示隸屬群組數量）；點該按鈕呼叫 `showVePemiBlngGrupsById(id)`（`LayoutContentPemis.vue:222,1090`），開啟權限隸屬群組對話框 `VePemiBlngGrups`。此對話框以「該權限被哪些群組使用」為視角，欄位依序為「權限群組名稱、是否使用、所屬權限名稱」（本列自己可改的在左、由其他權限帶來的在右）；勾選「是否使用」即把此權限掛入該群組，合併模式不另設欄，而是併入右欄代表本權限的那顆標籤（`VePemiBlngGrups.vue:143`），點該標籤左段即展開 OR / AND 清單。

兩入口的對話框是否可編輯，皆由各自清單頁的編輯模式 `isEditable` 決定並隨 `show()` 傳入（`LayoutContentGrups.vue:1163`、`LayoutContentPemis.vue:1124`）：`isEditable=true` 顯示「群組權限編輯」/「權限隸屬群組編輯」標題與功能列、可勾選與存檔；`isEditable=false` 顯示「（檢視）」標題（`grupEditCpemisForDisplay` / `pemiBlngEditGrupsForDisplay`），模式控制項與 checkbox 一律不可操作、隱藏功能列與 Save 按鈕，僅供唯讀檢視。

兩入口的存檔落點不同（皆寫入同一張 `grups` 表）：

- **VeCpemis（群組頁入口）**：對話框 Save 不直接打 API，而是把編輯後的 `cpemis` 字串 resolve 回群組頁；群組頁於 `showVeCpemisById.then` 寫回該列 `opt.rows[kr].cpemis` 並設 `isModified=true`（`LayoutContentGrups.vue:1166-1177`），真正寫入 DB 延到管理員按群組頁工具列的 `saveGrups` 按鈕 → `updateGrups`。
- **VePemiBlngGrups（權限頁入口）**：對話框 Save 自帶存檔，於 `clickSave`（第一行 `pm.resolve()`）→ fire-and-forget `doSave → core()` 內直接呼叫 `saveGrups(grupsNew)` → `$fapi.updateGrups(rows)` 即時寫入 DB（`VePemiBlngGrups.vue:1071,955`），存檔成功即關閉對話框。

寫入端點 `updateGrups` 經 hapi `verifyConn` 刪 Bearer 取 token → `checkToken(token)` 守門（`WWebPerm.mjs:1049,1063`），**token 無效 / 過期一律拒絕連線**。

- **E2E-002**
  - title: 管理員於群組頁對話框勾選權限並選 OR/AND 後存檔成功
  - description: 管理員在「編輯使用權限」對話框勾選某個權限的「是否使用」後，該列的模式控制項由淡色轉為可點，點開後可選 OR 或 AND；選 AND 並點對話框的儲存鈕，設定即回填到權限群組清單該列的「管控使用權限」欄，欄內摘要由「使用 2 項權限」改為「使用 3 項權限」；此時再按清單頁工具列的儲存鈕才真正寫入資料庫，完成後顯示「儲存權限群組數據成功」。適合一次調整某個群組的多項權限後再統一存檔。

    - 測試資料：base seed grups / pemis；取一既有群組列、選一原本未啟用的權限作勾選標的。

      1. 語意：對話框關閉；群組頁出現 `grupSaveGrupsSuccess` 提示；DB 該群組 `cpemis` 解析後對應權限為 `{ mode: 'AND', isActive: 'y' }`。

## spec 規則摘要

- **權限**：兩入口存檔皆經 `verifyConn → checkToken` 守門（有效 token 才可寫）；後端 `ckKey('name')` 確保 `grups` name 不可空 / 不可重複。
- **同源異視角**：群組頁入口（VeCpemis）與權限頁入口（VePemiBlngGrups）編輯的是同一份 `grups.cpemis`，僅切入視角不同——前者以「群組擁有哪些權限」逐列權限，後者以「權限被哪些群組使用」逐列群組。
- **存檔落點差異**：
  - VeCpemis（群組頁入口）Save **不即時打 API**，只把 `cpemis` 字串 resolve 回群組頁該列並設 `isModified=true`；真正 DB 寫入延到群組頁工具列 `saveGrups → updateGrups`。
  - VePemiBlngGrups（權限頁入口）Save **自帶即時 DB 寫入**，於 `core() → saveGrups → $fapi.updateGrups` 直接落庫、成功後關閉對話框。
- **唯讀檢視**：`isEditable=false` 時兩對話框皆顯示檢視版標題、隱藏功能列與 Save；群組頁入口之模式下拉淡化不可展開、權限頁入口之標籤模式段為純文字，checkbox 一律 disabled，僅供檢視不可改。
- **粒度**：對話框內切換防呆（無 name / 無目標）走 `$alert`；存檔結果（成功 / 失敗 / 空）一律走 `showCheckYes` DOM 模態；群組 name 錯誤 Save 擋存彙整為 `errInNames`。
- **契約**：兩入口的存檔按鈕 handler（VePemiBlngGrups `clickSave` / 群組頁 `saveGrups`）第一行 `pm.resolve()` 釋放按鈕視覺鎖後 fire-and-forget 各自的 `doSave` / `doSaveGrups`；`doSave` / `doSaveGrups` 內 `core() + .then/.catch/.finally`，`finally` 一處關 loading；`updateGrups` 失敗由 `okSave` 旗標短路後續、走 `grupSaveGrupsFail` 失敗提示。
