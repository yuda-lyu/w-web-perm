# 權限規則關聯流程

## 觸發

系統管理者於權限清單頁（`LayoutContentPemis.vue`）開啟編輯模式（`modeEdit` 開關，`isEditable=true`）後，每一列的 `crules` 欄渲染為一個按鈕（顯示「使用共 N 項對象」或「無使用任何對象」摘要文字）。點該按鈕觸發 `$dg.showVeCrulesById(props.row.id)`（`LayoutContentPemis.vue` 之 `crules` 欄 cell-render 按鈕），由 `showVeCrulesById`（`LayoutContentPemis.vue:showVeCrulesById`）依 row id 找到對應 pemi 列後，開啟權限規則關聯編輯對話框（`VeCrules.vue`，`LayoutContentPemis.vue:showVeCrulesById`）。

本對話框用途為編輯該權限（pemi）對各「管控對象」（target）的授權規則：`crules` 欄位以 JSON5 物件 `{targetId:'y'|'n'}` 形式記錄每個 target 是否被此權限啟用。對話框列出 store 中全部 `targets`（`VeCrules.vue:targets`、`VeCrules.vue:show`），每列一個 target、以 checkbox 表示啟用（`'y'`）或停用（`'n'`），提供全部啟用 / 全部停用 / 反向切換 / 刪除勾選對象等批次操作。

對話框「儲存」僅將編輯結果序列化為 `crules` 字串並 `resolve` 回權限清單頁（`VeCrules.vue:doSave`），由權限清單頁寫回該列的 `crules` 欄、`refresh`、設 `isModified=true`（`LayoutContentPemis.vue:showVeCrulesById`）；DB 實際寫入須由權限清單頁的 Save（`savePemis` → `updatePemis`）統一持久化。對話框本身不直接打 API。

是否可編輯由開啟時帶入的 `isEditable` 決定（`VeCrules.vue:show`）：`isEditable=false` 時為展示模式（標題顯示 `pemiEditCrulesForDisplay`，checkbox `disabled`，無功能區與儲存鈕）。

## 重要流程

- **E2E-001**
  - title: 系統管理者點 crules 欄按鈕開啟權限規則關聯對話框
  - description: 系統管理者在權限清單頁開啟編輯模式後，點某列「管控對象」欄的按鈕，按鈕文字為「使用共 N 項對象」或「無使用任何對象」，畫面開啟「編輯使用對象」對話框，逐列列出全部管控對象，每列有「對象名稱」與「是否使用」勾選框；該權限已授權的管控對象，其勾選框呈勾選狀態，其餘為未勾選。開啟對話框本身不會變更任何資料。便於檢視並調整某個權限涵蓋哪些管控對象。
  - flow:
    - 測試資料：base seed 既有 pemis 與 targets；編輯標的取一既有 pemi 列（其 crules 含部分 target 為 `'y'`）。
    - 操作：登入後台 → 進權限頁 → 開啟編輯模式 → 點該列 crules 欄按鈕。
    - 驗證：
      1. 語意：對話框出現於畫面，標題為 `pemiEditCrules`；表格逐列出現各 target 的 id 與 enable checkbox；既有為 `'y'` 的 target 列 checkbox 為勾選。
      2. 視覺：本 case 為多階段截圖，依序與下列 baseline 視覺一致（pixelmatch 容差）：①「來源權限列（點 crules 按鈕前）」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-001-1-source-row.png`；②「VeCrules 對話框初始態」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-001-2-dialog-open.png`。
    - 雙語：eng / cht 各一輪。
    - 清理：關閉對話框、不回填，DB 不變。
    - 備註：本案為本流程起點，其餘勾選／切換／儲存／取消案例皆以此對話框初始態為基準；對話框以 store 的 `targets` 逐列渲染（`VeCrules.vue:targets`、`VeCrules.vue:show`）。

- **E2E-002**
  - title: 系統管理者勾選某 target 為啟用（y）
  - description: 系統管理者在「編輯使用對象」對話框中，點某個尚未使用（未勾選）的管控對象之「是否使用」勾選框，該列隨即呈勾選狀態，且對話框出現儲存鈕。此時只是對話框內的暫時變更，尚未回填到清單。便於把一個管控對象加入某個權限的涵蓋範圍。
  - flow:
    - 測試資料：base seed pemis 與 targets；編輯標的取一既有 pemi，挑一個原為 `'n'` 的 target 列。
    - 操作：開啟對話框 → 點該 target 列 enable checkbox（n→y）。
    - 驗證：
      1. 語意：該 target 列 checkbox 由未勾選轉為勾選；對話框出現儲存按鈕（`isModified` 為真）。
      2. 視覺：本 case 為多階段截圖，依序與下列 baseline 視覺一致（pixelmatch 容差）：①「來源權限列（點按鈕前）」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-002-1-source-row.png`；②「對話框初始態（切換前）」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-002-2-dialog-open.png`；③「對話框內該規則列切 enable n→y」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-002-3-row-toggled.png`。
    - 雙語：eng / cht 各一輪。
    - 清理：不點儲存、關閉對話框，DB 不變。

  - flow:

      1. 語意：該 target 列 checkbox 由勾選轉為未勾選；對話框出現儲存按鈕（`isModified` 為真）。

    - 雙語：eng / cht 各一輪。
    - 清理：不點儲存、關閉對話框，DB 不變。

- **E2E-004**
  - title: 系統管理者儲存對話框回填 crules 字串至權限列
  - description: 系統管理者在「編輯使用對象」對話框勾選一個原本未使用的管控對象後，點對話框的儲存鈕，設定即回填到權限清單該列的「管控對象」欄，欄內按鈕文字中的項數隨之增加，清單頁並出現儲存鈕；此時尚未寫入資料庫，須再點清單頁工具列的儲存鈕才會真正存檔，完成後顯示「儲存權限數據成功」，若寫入失敗則顯示「儲存權限數據失敗」並附錯誤說明，變更仍保留在清單上可重按儲存。存檔後，使用這個權限的使用者，其最終授權即反映這項變更。適合一次調整某個權限的多個管控對象後再統一存檔。
  - flow:
    - 測試資料：base seed pemis 與 targets；編輯標的取一既有 pemi，切換其中一個 target 的 enable（改變啟用數量）。
    - 操作：開啟對話框 → 切換某原停用 target（`專案A/頁B/區塊A`）enable 為啟用 → 點對話框儲存按鈕（回填至權限列）→ 點權限清單頁工具列存檔按鈕（持久化至 DB）。
    - 驗證：
      1. 語意：對話框關閉；權限清單頁出現 `pemiSavePemisSuccess` 提示；DB 該 pemi 的 `crules` 含 `專案A/頁B/區塊A='y'`（新啟用）、原 `'y'` 之 target 維持。
      2. **解析後權限樹（權限系統核心，不可省）**：以 `getPermUserInfor` 查使用此權限之 user（peter 之群組 M1 使用 P1），其 resolved rules 的 active target 集合須因 P1 新啟用 `專案A/頁B/區塊A` 而**新增該 target**（peter 樹由 baseline 4 個增為 5 個）。**不可只驗 `crules` 設定存對、須驗解析後最終權限樹（外部應用實際查到的）**。預期值由 `getUserRules` 演算法算出。
      3. 視覺：本 case 為多階段截圖，依序與下列 baseline 視覺一致（pixelmatch 容差）：①「來源權限列（點按鈕前）」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-004-1-source-row.png`；②「對話框初始態」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-004-2-dialog-open.png`；③「對話框內規則列切 enable（存檔前）」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-004-3-row-toggled.png`；④「權限頁存檔成功 modal」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-004-4-save-back.png`；⑤「存檔後該權限列摘要已反映規則變更（數據變更證明）」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-004-5-data-changed.png`。
    - 雙語：eng / cht 各一輪。
    - 清理：不點權限頁 Save（回填僅存於前端暫存），重整頁面即捨棄，DB 不變。
    - 備註：解析後權限樹之數字（5 個）在新舊合併規則下相同（peter 之群組 M1 僅含 OR 權限，不涉及 AND 項；2026-10-21 以 `getUserRules` 對種子資料實算，兩版皆為 5 個），不受 ADR-033 影響。本案為對話框儲存回填路徑之成功案例；DB 實際寫入留待權限頁存檔。

- **E2E-005**
  - title: 系統管理者取消對話框不變更 crules

  - flow:
    - 測試資料：base seed pemis 與 targets；編輯標的取一既有 pemi。
    - 操作：開啟對話框 → 切換某 target enable → 點對話框關閉按鈕。
    - 驗證：
      1. 語意：對話框關閉；權限清單頁該列 crules 欄按鈕文字與開啟前相同（未回填），不因取消產生變更。
      2. 視覺：本 case 為多階段截圖，依序與下列 baseline 視覺一致（pixelmatch 容差）：①「來源權限列（點按鈕前）」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-005-1-source-row.png`；②「對話框初始態」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-005-2-dialog-open.png`；③「對話框內規則列切 enable（Close 前）」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-005-3-row-toggled.png`；④「框該權限列、摘要維持原值未變（取消放棄變更證明）」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-005-4-cancelled-grid.png`。
    - 雙語：eng / cht 各一輪。
    - 清理：本案取消未回填，DB 不變，無需清理。

- **E2E-006**
  - title: 非編輯模式開啟 VeCrules 僅供唯讀檢視
  - description: 系統管理者未開啟編輯模式即點權限清單某列「管控對象」欄的按鈕時，開啟的是「展示使用對象」對話框：內容與編輯時相同，但沒有功能列與儲存鈕，每列的勾選框也不能改，只能檢視該權限目前涵蓋哪些管控對象。此欄按鈕不受編輯模式影響，隨時可點開檢視。與其他關聯對話框不同，本對話框只有「是否使用」一個勾選欄，沒有 OR 或 AND 的合併模式欄。適合查看而不想誤改設定時使用。
  - flow:
    - 測試資料：base seed pemis 與 targets；取權限列 row 0（權限P1）作開啟標的。
    - 操作：登入後台 → 進權限頁 → 點「編輯模式」開關關閉編輯模式 → 點該列 `crules` 欄按鈕。
    - 驗證：
      1. 語意：對話框標題為展示模式鍵 `pemiEditCrulesForDisplay`（cht `展示使用對象` / eng `Rules of permission`，與編輯版 `pemiEditCrules` 相異）；頁面無對話框儲存按鈕（`hasSaveBtn=isEditable && isModified`，`isEditable=false` 恆不渲染，`VeCrules.vue` template 之 `hasSaveBtn`）；各 target 列 enable checkbox 皆 `disabled`（本對話框無 mode 下拉欄）。
      2. 視覺：與 baseline 視覺一致（pixelmatch 容差）：「VeCrules 唯讀檢視對話框」`test/pics/rela-pemi-rule/rela-pemi-rule-{eng,cht}-E2E-006-readonly-view.png`。
    - 雙語：eng / cht 各一輪。
    - 清理：本案唯讀，不改 DB，無需清理。
    - 備註：`crules` 欄按鈕不受編輯模式影響恆渲染（`LayoutContentPemis.vue` 之 `crules` 欄 cell-render），`showVeCrulesById` 隨 `isEditable=vo.isEditable` 傳入（`LayoutContentPemis.vue:showVeCrulesById`）；與 E2E-004 共同覆蓋 `isEditable` 兩分支。`crules` 值為純 `'y'`／`'n'` 字串，故本對話框無 OR／AND 之 mode 欄。

- **E2E-007**
  - title: 權限規則重複列且有勾有不勾時顯示警告
  - description: 外部應用以陣列形式寫入權限的規則時，同一個管控對象可能被列了兩次，一列勾選、一列不勾選，系統取不勾選。系統管理者在權限清單頁看到該權限列「管控對象」欄按鈕左側出現警告圖示，滑鼠停留會提示哪個管控對象重複列出且有勾與沒勾並存，系統視為沒勾選。點該欄按鈕開啟「編輯使用對象」對話框，這個管控對象的列顯示為未勾選，對象名稱左側同樣有警告圖示與相同提示。系統管理者勾選這一列並點儲存，再按清單頁工具列的儲存鈕寫入後，重複列合併為單一個勾選的對象，使用這個權限的使用者即取得該對象的授權。便於發現外部資料的矛盾並整理。
  - flow:
    - 測試資料：base seed pemis / targets；案例前置（非使用者操作）：經外部同步端點（`/syncAndReplaceTabs`，`from` 為本案專屬分區）推入權限 `dup-p`（id `id-dup-p`），其 `crules` 為陣列形式 `[{"name":"專案A/頁A/區塊A","isActive":"y"},{"name":"專案A/頁A/區塊A","isActive":"n"},{"name":"專案A/頁C","isActive":"y"}]`；群組 `dup-pg`（id `id-dup-pg`，`cpemis` 為 `{"dup-p":{"mode":"OR","isActive":"y"}}`）；使用者 `dup-pu`（id `id-dup-pu`、email `dup-pu@example.com`，`cgrups` 為 `{"dup-pg":{"mode":"OR","isActive":"y"}}`）。登入身分為系統管理者 token `sys`。
    - 操作：登入後台 → 點「權限」頁籤 → 觀察 dup-p 列「管控對象」欄 → 點該欄按鈕 → 觀察 `專案A/頁A/區塊A` 列 → 勾選該列的「是否使用」→ 點對話框儲存 → 點權限頁工具列儲存。
    - 驗證：
      1. 語意：清單 dup-p 列「管控對象」欄按鈕左側有警告圖示，其 `title` 為 `warnRuleConflict` 代入 `專案A/頁A/區塊A`（eng：`Listed more than once, with both checked and unchecked: 專案A/頁A/區塊A. It is treated as unchecked (n).`；cht：`重複列出且有勾與沒勾並存：專案A/頁A/區塊A。系統視為沒勾選（n）。`）；按鈕文字為「使用共 1 項對象」（cht）／`Has 1 rule(s)`（eng）；其餘權限列無警告圖示。對話框：`專案A/頁A/區塊A` 列「是否使用」未勾選且名稱左側有相同 `title` 之警告圖示；`專案A/頁C` 列已勾選、無圖示；其餘管控對象列未勾選且無圖示；勾選該列後圖示仍保留（提示反映開啟時的資料）。點對話框儲存後對話框關閉，dup-p 列警告圖示消失、按鈕文字為「使用共 2 項對象」、清單頁出現儲存鈕；點儲存出現 `pemiSavePemisSuccess`；DB dup-p 之 `crules` 解析後為物件形式，`專案A/頁A/區塊A` 與 `專案A/頁C` 皆為 `'y'`。未點清單頁儲存前 DB 不變。

## spec 規則摘要

- **流程角色**：本對話框為「回填器」——只負責把該權限對各 target 的啟用規則編成 `{targetId:'y'|'n'}` 字串 resolve 回權限清單頁；DB 寫入不在本流程，須由權限清單頁 Save（`savePemis` → `updatePemis`）統一持久化。
- **資料模型**：`crules` 為 JSON5 物件字串，key 為 target 的路徑式 id（`src/schema/tables/targets.mjs` 之 `settings.id` 註「儲存對象路徑，不同階層用句點分開」，樣本 id（`funTest`）為斜線路徑如 `專案A/頁A/區塊A`），value 為 `'y'`（啟用）或 `'n'`（停用）；`crules` 內未列之管理對象視同 `'n'`（`R-AUTH-MERGE-00` 第 1 條，ADR-033），與顯式 `'n'` 等價。
- **授權不變與合併規則（`R-AUTH-MERGE-00`，ADR-033，2026-10-21）**：本對話框為兩態（勾＝`'y'`、不勾＝`'n'`），不做三態；對話框列出 store 全部 targets，故重存把原本「未列」之管理對象寫成顯式 `'n'`，不改變授權。伺服端合併與 `crules` 之鍵序、陣列元素序無關，故存檔不保留原鍵序（原載「鍵序經 `keepKeyOrder` 保留原序」2026-10-21 起不成立）；同一 `crules`（陣列形式）重複列同名規則時所有列皆 `'y'` 才 `'y'`，編輯器經 `cvKpToObj` 解碼採同一規則。
- **衝突提示（ADR-035 決定 a，2026-10-21 run05，使用者原則「收嚴＋增加提示」）**：重複列且有勾有不勾之管理對象，系統取沒勾選（run04 已收嚴），本輪補提示：權限清單頁 `crules` 欄按鈕左側與本對話框該對象列名稱左側顯示警告圖示＋tooltip（`warnRuleConflict`，E2E-007）；全 `y` 或全 `n` 之重複不算衝突；無衝突之資料列畫面與修改前逐像素相同（既有標準圖不變）。
- **targets 來源**：對話框列出的 target 一律取自 store `targets`，逐 target 一列；序列化時僅以實際存在的 target id 為 key（不存在的 target 不會憑空產生列）。
- **互動模型**：對話框內 toggle / 全部啟用 / 全部停用 / 反向切換 / 刪除勾選對象只改 `opt.rows` 並設 `isModified=true`，**不即時序列化**；按儲存才於 core() 一次序列化並 resolve。
- **儲存 / 取消分支**：
  - 儲存 → `clickSave`（第一行 `pm.resolve()` 釋放按鈕視覺鎖）→ fire-and-forget `doSave` → core() 序列化 → `pm.resolve(crules)` → 權限頁回填、`refresh`、權限頁 `isModified=true`。
  - 取消 → `clickClose` → `pm.reject('close window')` → 權限頁 `.catch` 吞掉、不回填、不變更。
- **編輯權限**：`isEditable=false`（展示模式）時無功能區與儲存鈕、checkbox `disabled`，僅供檢視。
- **契約**：`clickSave` 第一行 `pm.resolve()` 釋放按鈕視覺鎖後 fire-and-forget `doSave`；`doSave` 內 `core() + finally`，`finally` 一處關 loading（`VeCrules.vue:doSave`）。本對話框不打 API（只 resolve 回權限頁），故刻意保留此寫法、不套 `runSubmit`；打 API 之送出鈕不得如此（ADR-025）。
- **單例**：對話框開啟中再次 `show()`（如焦點留在開啟鈕時按 Enter）時，舊階段之等待者視同關閉（`reject('close window')`，權限頁 `.catch` 吞掉），不再永久懸置（ADR-025，2026-09-29）。
- **粒度**：對話框無欄位驗證錯誤；非預期取不到 target / pemi 之 id 或資料時以 `$alert` toast 呈現；權限列 crules 欄摘要為粗粒度（僅啟用數量，不列個別 target id）。
