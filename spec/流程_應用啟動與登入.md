# 應用啟動與登入流程

## 觸發

瀏覽器使用者開啟後台網址，Vue 根元件 `App.vue` 於 `beforeMount` 啟動：先 `setVo` 綁定廣播用 vo、`setLang` 依 `window.___pmwperm___.language` 初始化語系，再以 `wui('wperm', ...)`（`w-ui-loginout`）建立登入輔助物件並呼叫其 `login()`，由 token（網址 query 或 `localStorage` 的 `wperm:userToken`）取得使用者資訊。

登入結果分兩路：成功則回呼 `loginSuccess`，將 `connState` 設為 `csLogin`、寫入 `userToken` 與 `userSelf`；失敗則回呼 `loginError`，將 `connState` 設為 `csErrLogin`、清空 `userToken`，並於正式環境重導至 `urlRedirect`（開發環境延遲 60 秒後重導）。

畫面在 `ready` 為真之前一律由 `LayoutState.vue` 依 `connState` 顯示連線狀態畫面（`csIng` / `csLogin` / `csLogout` / `csErrConn` / `csErrLogin` 五種）。`ready`（`App.vue` 之 computed `ready`）需同時滿足 `connState==='csLogin'` 且 `webInfor` 為非空物件才為真，為真後切換為 `Layout.vue` 殼層，內含 `LayoutContent.vue` 五頁籤（`mmStaInfor` / `mmTargets` / `mmPemis` / `mmGrups` / `mmUsers`）。`webInfor` 由 `main.js` 的 `WServHapiClient` 取得 `$fapi` 後呼叫 `getWebInfor` 取回並 commit、同時 commit `syncState=true`。

## 重要流程

本流程五案皆於 e2e-init 以「後端注入語系」驗證（後端以指定 `language` 啟動 → dist 注入 `window.___pmwperm___.language`，連線前狀態畫面走 fallback、登入後殼層走 `webInfor.language`，皆非前端 `setLang` 切換）；案序依使用者觀察之時序：連線中 → 已登入過場 → 登入成功（五頁籤）→（失敗分支）拒絕登入 / 無法連線。

- **E2E-008**（語意斷言由 `e2e-init` `E2E-008-veto-by-deployer [eng／cht]` 實作〔2026-10-24 perm-run01 本輪，P-7〕；不設標準圖：拒絕登入畫面見 E2E-004，本案登入失敗後立即轉址，畫面不停留）

  - description: 即使登入者是系統管理員，所屬單位的登入授權仍可因非角色因素（例如連線來源網段、系統別）否決其進入權限後台。此時系統不是顯示「無權進入權限後台」（那是專屬非系統管理員的提示），而是視為一般的登入失敗：在正式環境立即轉址至設定的轉址網址（開發環境延遲 60 秒，期間畫面停在「拒絕登入」）。需要使用後台者請洽所屬單位調整登入授權。

    - 測試資料：base seed；以管理員令牌 `sys` 經共用層於 `users` 加入一位管理員（id `id-for-deny`、name `deny`、email `deny@example.com`、`isAdmin='y'`、`isActive='y'`、`cgrups` 為 `{}`）；其令牌 `{token-for-deny}` 於 `srv.mjs` 之 `verifyClientUser` 被否決（模擬部署方因非角色因素否決，非 production 才有）。後端以 `language=eng` 或 `language=cht` 及 `urlRedirect` 為不存在之路徑之臨時設定啟動。
    - 操作：以乾淨瀏覽器開啟後端服務之網址（`127.0.0.1`，非開發環境；`?token=` 帶 `{token-for-deny}`），等待登入流程結束。
    - 驗證：
      1. 語意：`/api/getUserByToken` 之回應 `state='error'`、`msg='userNoPermission'`（不是 `userNotAdmin`）；頁面隨即轉址至 `urlRedirect`（網址含轉址路徑）。
      2. 視覺：不設（登入失敗後立即轉址，畫面不停留；拒絕登入畫面本身見 E2E-004）。
    - 雙語：eng / cht 各一輪。
    - 清理：測試後還原 `users` 三表快照（移除 deny）、還原 `./settings.json`。
    - 備註：規則帳本 R-ADMIN-ONLY-01、R-APP-TOKEN-01（P-7）。畫面不寫出否決理由：部署方的否決原因（網段、系統別等）屬部署方政策，套件只得知「被否決」，固定回 `userNoPermission`；理由須由部署方在其登入授權處（或轉址目標頁）向使用者說明。若要在權限後台自身的畫面顯示否決原因，須新增連線狀態與標準圖並取消即時轉址，屬另案裁示。

## spec 規則摘要

- **啟動序**：`App.vue` `beforeMount` 依序 `setVo` → `setLang` → 建立 `wui('wperm')` → `login()`；`webInfor` / `syncState` 由 `main.js` 的 `WServHapiClient` 經 `getWebInfor` 另路回填。
- **進入後台條件**：`ready`（`App.vue` 之 computed `ready`）須同時 `connState==='csLogin'` 且 `webInfor` 為非空物件；任一未滿足皆停留在 `LayoutState` 連線狀態畫面。
- **狀態畫面**：`LayoutState` 依 `connState` 六分支渲染（`csIng` / `csLogin` / `csLogout` / `csErrConn` / `csErrNotAdmin`〔perm-run01 增〕，其餘落 `v-else` 的 `csErrLogin`）；連線前文字由 `mUI.mjs` 的 `kpFallback` 提供雙語預設，後端語系載入後改取 `kpText`。
- **登入分流**：`login()` 成功 → `loginSuccess` 設 `csLogin` + 寫 `userToken` / `userSelf`；失敗 → `loginError` 設 `csErrLogin` + 清 `userToken`，並重導 `urlRedirect`（開發環境延遲 60 秒、正式環境即時）。**例外（perm-run01，R-ADMIN-ONLY-01）**：後端回 `userNotAdmin`（登入者不是 perm users 表中有效之系統管理員，即使部署方放行）時改設 `csErrNotAdmin`（「無權進入權限後台」）+ 清 `userToken` 並**停在該畫面、不轉址**（E2E-007）；後台登入檢查只限系統管理員，一般使用者以令牌查自己權限樹走 `/api/getPerm`（不經本流程）。
- **i18n 重渲染**：`setLang` 更新 `lang` / `kpText` 後以 `forceUpdate` 廣播全組件重繪（`mUI.mjs:setLang,forceUpdate`）；語言選單僅在 `webInfor.showLanguage==='y'` 時顯示（`Layout.vue:mounted` 之 `firstSetting` 段；窄版時位於漢堡選單內，ADR-022）。
