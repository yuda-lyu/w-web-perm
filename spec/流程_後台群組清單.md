# 後台群組清單流程

## 觸發

管理員（瀏覽器使用者，經 w-ui-loginout 登入取得有效 token、`connState='csLogin'`）進入後台後，於 `LayoutContent.vue` 左側導覽點「權限群組」（`mmGrups`）進入群組清單頁（`LayoutContentGrups.vue`）。此頁以 ag-grid（`WAggridVue`）列出 `grups` 表，欄序為 名稱 / 說明 / 管控使用權限（`cpemis`）/ 管控所屬使用者（`belongUsers`）——本群組自己管控的在左、由上層帶過來的在右（2026-09-16 依業主要求對調，見 `LayoutContentGrups.vue` `data` 之 `tabKeys` / `tabKeysPick` / `tabKeysShow`）；提供：編輯模式切換、顯示欄位挑選、新增 / 複製 / 刪除 / 儲存、`cpemis` 群組擁有權限入口按鈕、`belongUsers` 群組成員入口按鈕。

寫入端點 `updateGrups` 經 hapi `verifyConn` → `checkToken(token, apiType)` → `getAndVerifyClientUser` 守門（`server/WWebPerm.mjs`：`verifyConn`、`p.checkToken`、`getAndVerifyClientUser`）：token 須可由部署方 `getUserByToken` 解出使用者、該使用者須存在於 perm `users` 表且 `isActive='y'`（`getTokenUser`）、並通過部署方 `verifyClientUser(user, from)`（資料通道之 from 為 apiType，如 `main`），**任一不符即拒絕連線**（ADR-015，2026-09-29 業主裁示資料通道採嚴格預設）；是否限定管理員由 `verifyClientUser` 決定。

## spec 規則摘要

- **權限**：所有 `updateGrups` 寫入經 `verifyConn` → `checkToken` → `getAndVerifyClientUser` 守門（token 須有效、其使用者須在 perm `users` 表且 `isActive='y'`、並通過部署方 `verifyClientUser` 才可寫；ADR-015 嚴格預設）；是否限管理員由 `verifyClientUser` 決定。
  - 修改留痕（2026-09-29）：原載「經 `checkToken` 守門（有效 token 才可寫）」並以行號引用 `WWebPerm.mjs`——行號已漂移，且未載 perm `users` 表／`isActive` 要求；ADR-015 業主裁示資料通道維持嚴格預設後，依現行碼（`WWebPerm.mjs` 之 `p.checkToken` → `getAndVerifyClientUser`）改寫本段、觸發段與執行流程之守門行。
- **粒度**：name 欄錯誤走 cell 警告 icon + tooltip（具體 2 種：空 / 重複，僅前端視覺提示）；Save 擋存彙整與操作主要結果（前端 `errInNames` / rows 空 `grupAddEmpty` / 成功 `grupSaveGrupsSuccess` / 失敗 `grupSaveGrupsFail`）一律走 `$dg.showCheckYes` 持久 modal（System message 對話框 + OK 鈕，對齊全域 §5.1 禁原生 alert）；非預期例外與防呆（`grupEditBlngNoGrupId` / `grupEditBlngNoGrupData`）走 `$alert` toast 低調呈現。
- **邊界**：
  - `grups` **name 不可空 / 不可重複**（前端 `errItemsByName` 警告 + 後端雙守門：`ckKey('name')` 驗空值／非字串、`findTouchedDup` 驗唯一〔精確 `===`、只拒本次新增或修改所造成之同名，F-02、ADR-034〕，`procCore.mjs:updateTabItems`）。庫內歷史既有重複（僅外部同步可造成）原樣送回不被伺服端拒絕，且改以 `id` 對應差異（改名不被靜默吞掉）；**前端 `errItemsByName` 自 2026-10-21 run05 起與伺服端同一判準（`getNameErrs.mjs`／`findTouchedDup.mjs`），只擋本次造成或觸及之同名，歷史同名顯示警告圖示（`warnNameHistDup`）而不擋存**（E2E-011、E2E-012；原載『前端仍對歷史重複標警告並擋存』自此不成立，實測確認見〈已知落差〉）。
  - CRUD 為「單頁多動作 + 批次儲存」模型：`addItem` / `copyItem` / `deleteItemsCheck` / `showVeCpemisById` 只改 `opt.rows` 並設 `isModified=true`，**不即時打 API**；一律 Save 才以 `ltdtDiffByKey`（依 `name`）批次 del / insert / save 送出。`showVeGrupBlngUsersById` 不改 `opt.rows`、不設 `isModified`（then / catch 皆空）。
  - 稽核欄位（`userId` / `time*`）前端填 `{待自動給予}` 佔位符，後端 `procOrm` 補實值。
  - `belongUsers` 為衍生顯示欄位（由使用者 `cgrups` 反查群組成員數），非 grups 表持久欄位；其按鈕開 `VeGrupBlngUsers` 對話框後不回填本列資料；該對話框於編輯態自行儲存時直接呼叫 `updateUsers`（ADR-014），不經本頁 Save。
  - `cpemis` 為群組所擁有權限清單（JSON5 字串），其按鈕開 `VeCpemis` 對話框後將 resolve 字串寫回該列並設 `isModified=true`，於 Save 隨列送出。
- **引用連帶（2026-10-22 run06，ADR-036、規則帳本 R-REF-CASCADE-01）**：群組被刪除或改名時，引用它之 `users.cgrups` 於同一次寫入內連帶處理。**刪除**：移除該引用（任何 mode、含停用項；以 AND 引用者限制解除，授權可能變多，效果等同舊版「找不到即忽略」；不採「被引用則禁止刪除」，使用者 2026-10-21 裁示），刪除前以確認框提示筆數與其中以 AND 引用者（E2E-005、E2E-014）；刪除後以同名新增（新 id）之群組不繼承舊引用。**改名**（同 id 異名；伺服端 `opt.cascadeRename` 預設 `true`）：引用字串連帶改為新名稱，儲存前以確認框預覽（E2E-015），成功訊息附筆數；`cascadeRename:false` 時不連帶、不產生改名相關拒絕（E2E-017）；改名被拒（新名撞懸空名、歷史同名組改名、容器內新舊名相撞、無法安全改寫）整次拒存、四表零變更並顯示固定語系鍵訊息（E2E-016）。引用端先寫、主體後寫，任一步失敗以寫入前原值補償還原引用端；取鎖階層 targets、pemis、grups、users。外部同步（同一 `from` 內依穩定 id）同樣適用，見 `流程_外部應用同步權限資料.md`〈同步之引用連帶〉。
- **契約**：`saveGrups` 為按鈕 handler，把 `msg.pm` 交給 `doSaveGrups`、不於 handler 解鎖；`doSaveGrups` 以 `$ui.runSubmit('saveGrups', …)` 包覆 `core() + .catch + .finally`，`finally` 一處關 loading；`updateGrups` 失敗由其 inline `.catch` 顯示 `grupSaveGrupsFail` 持久 modal，並以 `okSave` 旗標 `if (!okSave) return` 短路後續。（修改留痕 2026-09-29：原載「第一行 `msg.pm.resolve()` 釋放視覺鎖後 fire-and-forget」，已由 ADR-025 改寫。）
- **送出入口與連按**（ADR-025）：入口只有 Save 鈕（WButtonCircle，滑鼠與焦點在鈕上之鍵盤 Enter 同走元件之 `clickBtn`）。全頁 loading 與訊息框（WDialog）只擋滑鼠、不搶焦點；按鈕鎖（`promiseUnlock`）涵蓋請求期間，流程狀態（`runSubmit('saveGrups')`）涵蓋至結果訊息框關閉，期間再觸發即略過。後端以「updateTabItems:grups:操作者 id」占位：同一操作者並行儲存之第 2 次回 `saveInProgress`、不寫入；新增 / 複製之列帶 `_isNew`，依序重送同一包（第 1 次已建立該列）回 `saveNewRowExists`、整包不寫入（本表 diff 依 `name`，重送之新列會被當「修改」以前端佔位字覆寫建立者與建立時間，故以 id 比對擋下）。不同操作者之並行仍由 kmx 序列化、各自成功。
